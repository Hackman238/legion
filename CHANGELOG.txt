LEGION Unreleased

* Portability fixes adopted from Denys Kolomiiets' macOS port (pull request #53): tool processes never inherit Legion's stdin (katana and httpx blocked forever on a piped stdin), nmap plans leave out OS detection when raw sockets are unavailable instead of failing, the nmap HTML stylesheet is found under Homebrew as well as /usr/share, katana uses the repeated `-kf` form modern releases require and a 5-minute crawl cap, the log directory honours `LEGION_LOG_DIR` and falls back to the temp directory when the cache directory is not writable, tool paths default to bare names resolved from PATH, `exec-in-shell` works without getent, and `.dockerignore` keeps projects and secrets out of images.
* The three database entity modules still imported `six`, which 0.8.0 dropped from the requirements; a clean install now starts. SQLAlchemy 2 is what the code runs on and the requirements say so (the 1.4 pin, the urllib3 1.x pin and the selenium 4.9.1 pin are gone).
* Removed the embedded Shodan API key from `scripts/python/pyShodan.py`; the key comes from the tool settings or `SHODAN_API_KEY`. Anyone who used that key should consider it exposed and rotate it.

LEGION 0.8.0

* Removed the legacy Qt desktop UI. `python legion.py` now starts the web interface; the headless CLI and MCP server are unchanged. PyQt6, qasync and the X11/xvfb packages are no longer dependencies, and the Nmap importer no longer needs Qt.
* Dropped the unused `asyncio` backport and `six` from the requirements.
* Fixed `legion.py --mcp-server`, which started the MCP server with its stdin and stdout discarded (so it could never answer) and then fell through to the UI; it now serves JSON-RPC on the invoking process's stdio. The first-run copy of `legion.conf` no longer depends on the current directory.
* Web security: state-changing requests from other origins (cross-site form posts, pages on other local ports, rebound DNS names) are rejected, uploads are capped, and API errors are always JSON.
* Scheduler: nmap `*-brute` scripts and `unsafe=1` script arguments are classified as risky (they ran without approval under every preset), an AI plan whose candidates are all filtered out falls back to deterministic planning instead of re-admitting blocked actions, approved actions re-check the current policy before running, rejecting an executed approval no longer rewrites the decision log, tool JSON with non-numeric counters no longer aborts a run, and non-object provider responses are reported as provider errors.
* Scheduler performance: the evidence-graph sync is skipped when a host's target state has not changed, execution records share artifact nodes with the state sync instead of duplicating them, and the approval, decision-log and execution tables are indexed by host (indexes are added after the column migrations, so projects from older releases open cleanly).
* Web runtime: credential-capture listeners (Responder, ntlmrelayx) are no longer killed after 300 s of silence, hiding a running process stops it, switching projects waits for every running job, project bundles archive a consistent database snapshot, a cancelled scan is recorded as cancelled, scan history no longer shows finished imports as queued, deleting a host removes its evidence-graph nodes, restored bundles live in Legion's temp folder, and an invalid legion.conf is rejected instead of written.
* Web UI: cancelled jobs end their wait immediately, the hosts/services tables are no longer overwritten by the capped snapshot, credential captures refresh live, project switches clear every filter, the live socket reconnects with backoff and detects a silent connection, double clicks no longer queue duplicate jobs, and modals manage keyboard focus.
* Importer and parsers: a `<host>` without an address is skipped instead of aborting the import, vulners results for products without a CPE are imported, host scripts are no longer hidden by same-named port scripts, and a hand-edited or non-UTF-8 `legion.conf` (duplicate sections, malformed rows) falls back to defaults instead of crashing every entry point.
* Headless CLI scans the same normalised targets it imports (URLs become hostnames) and uses the configured nmap path; tool install plans never block on a sudo password and no longer rely on a login shell that resets PATH.
* Database: deleting a host removes its ports, services, scripts, CVEs, notes and OS rows; keyword filters treat `%` and `_` literally; process-repository queries always release their session and use standard SQL quoting.
* Web UI workflow: every data table sorts by clicking a header and filters by typing, pending approvals have Approve All and Reject All, confirmation dialogs replace browser prompts, status messages are toasts, the Services panel and graph are visible by default, Font Awesome is bundled for offline labs, and the Running/Finished process table shows start time and elapsed time.
* Host Detail: CVSS scores map to severity bands, CVE rows show the Exploit-DB reference and a clickable source, database ids are hidden, IPs, CVE ids and manual-test commands have copy buttons, the operator note is edited in place, and every port has a Run Tool button that pre-fills the manual tool picker.
* Bulk and batch operations: host rows have checkboxes with Rescan, Dig Deeper, Screenshots, Run Tool and Remove for the selection (`POST /api/workspace/hosts/bulk-action`), the manual tool picker can run one tool against every listed target (`targets[]` on `/api/workspace/tools/run`), and Submitted Scans rows can be re-run with their recorded settings (`POST /api/scans/history/<id>/rerun`).
* Import and projects: nmap XML and target lists can be uploaded from the browser (`/api/nmap/import-xml-upload`, `/api/targets/import-upload`), nmap `.gnmap` and masscan XML, JSON and list reports are converted and imported through the same path (web, headless and MCP), the Open Workspace picker lists, renames and deletes saved projects (`/api/project/rename`, `/api/project/delete`), and Save As suggests known project paths.
* Exports: Export JSON/CSV export the whole project (down hosts, every service, process and decision) instead of the capped UI snapshot, and every table has its own CSV/JSON download (`/api/export/table/<name>.<csv|json>`).
* Scheduler UI: execution traces (Logging > Executions), findings (Misc > Findings), a plan preview in the manual tool picker, and the pre-approved and blocked command families with per-family clear/block controls (`POST /api/scheduler/family-policy`) are reachable from the ribbon.
* Tools: the Tools panel lists every configured port action (not a fixed whitelist) and marks which executables are installed; vulners CVSS scores are stored as severities.
* Security: `--web-token` / `LEGION_WEB_TOKEN` protect the UI and API (login page, cookie, `Authorization: Bearer`); a token is generated and printed automatically when `--web-bind-all` is used without one. Saving legion.conf reports whether the running instance reloaded it.
* Headless CLI: `--discovery` and `--staged-scan` work again and run the `[StagedNmapSettings]` stages, `--nmap-args` is appended to every stage, `--nmap-xml` imports reports without scanning, and `--project` works inside an existing or new `.legion` file.
* MCP server: speaks the MCP protocol over stdio (`initialize`, `tools/list`, `tools/call`) and exposes host and service inventory, scans, imports, tool runs, scheduler runs, jobs, processes and scan history alongside the existing graph, findings and report tools.
* Interface: optional light theme (Interface Settings, stored per browser), host and service filters are remembered per project across reloads, and the import, open and save dialogs remember the last paths used.
* Documentation: the REST API is documented in docs/api.md; the README lists `LEGION_TMPDIR`, `LEGION_PIPETTES_PATH`, `LEGION_WEB_TOKEN` and `/health`; dead legion.conf sections (`BruteSettings`, `GUISettings`, `PortTerminalActions`) are gone.

LEGION 0.7.1

* Fixed the desktop UI failing to start (missing imports after the module split) and segfaulting on exit; Qt objects are now torn down in order on every exit path.
* Fixed nmap import crashes: an import error or a bad XML no longer aborts the application, overlapping imports are queued instead of silently dropped, cancel state is per import, and a malformed or missing XML fails the import instead of reporting success.
* Fixed data-loss paths around Save As: the replace prompt appears again, a refused or cancelled save no longer discards the project, saving a temporary project onto its own path keeps it, importers follow the reopened project, and scans still running across a Save As are imported.
* Fixed CVE handling: a partial vulners re-scan no longer wipes CVEs for other ports or manually added entries, old-version CVEs are dropped after an upgrade, OS accuracy is stored and compared numerically, and MAC/vendor/uptime are filled on re-import.
* Fixed per-host reports including other hosts' findings and credentials, the detection-risk policy setting having no effect, and approval lookups matching the wrong approval number.
* Hardened process handling: a killed tool is reported as killed whatever its exit code, stale PIDs from a crashed session are never signalled, interrupted rows are reset when a project opens, user kills no longer show a crash dialog, and the process queue no longer leaks slots or timers.
* Web runtime: tool output survives non-UTF-8 bytes, output polling and previews return only the requested slice, the host view reads each process output once, N+1 queries in the workspace views are batched, duplicate jobs are prevented, failed restores clean up, and RFC1918 sweeps survive a bad chunk.
* Scheduler: Claude truncation retry and non-JSON handling, LM Studio reasoning output and model-cache invalidation, race-safe graph upserts with unique keys on legacy tables, stale screenshot/artifact nodes pruned, per-host locking for state updates, a per-engine schema cache, and indexed evidence lookups.
* Importer and CLI: Exploit-DB lookups are offline (no git pull during imports) and work with both pyexploitdb and pyExploitDb package names; hostname targets are updated in place when resolved; headless mode handles nmap failures, leaves no temp folders and exports every CVE column; commits are batched and hot columns are indexed.
* MCP server survives malformed or oversized requests and starts with a temporary project; governed discovery adds to the open project instead of replacing it.
* Test suite grows from 723 to 937 tests, exits cleanly, and the fixtures that were never committed (ignored by `*.xml`) are restored.
* README rewritten and shortened; pipette documentation moved to docs/pipettes.md.

* Added local secret-store support for provider and integration credentials, keeping AI/provider keys out of the plaintext scheduler preference file when an OS-backed or encrypted local store is available.
* Improved project bundle fidelity with stricter artifact export/restore handling, safer restore staging before swapping the active project, path rebasing for restored workspaces, and clearer restore failure behavior for legacy or damaged `.legion` projects.
* Expanded workspace analysis with service/open-port filtering, service port visibility, graph filtering tied to host filters, improved host/service selection sync, stronger OS enrichment from service evidence, and phone/OOB/device category classification improvements.
* Added bundled pipettes: Cisco Smart Install exposure checks, internal SMTP discovery and optional SPF review, Windows SMB/RDP discovery, and IPMI/iDRAC/iLO out-of-band management discovery.
* Improved scan/runtime reliability with unique Nmap output prefixes, screenshot target selection fixes, artifact cleanup paths, process/tool execution extraction, and Responder/NTLMRelay workspace handling.
* Expanded route, schema, pipette, bundle, scheduler, MCP, workspace, graph, and tooling tests to lock down cross-surface behavior as the web/runtime split continues.

LEGION 0.5.2

* Easy mode host discovery now defaults to `-Pn` so hosts that block ping probes are still scanned/imported.
* Easy mode adds explicit `Stealth` and `Include UDP` toggles, with stealth behavior tied to `-sS` and fragmentation (`-f`) only when stealth is enabled.
* Easy mode adds `Broad RFC1918 Discovery (Balanced)` with selectable canary sample sizes (`16`, `32`, `64`, `128`) and automatic RFC1918 target defaults (`10/8`, `172.16/12`, `192.168/16`) when broad mode is selected.
* Broad discovery now runs in controlled canary/full chunks to provide progressive imports and avoid sparse, long-gap updates during very large subnet sweeps.
* Hard mode defaults the Port Scan Options selection to `TCP SYN` (`-sS`).
* Improved process/database hardening to reduce shutdown/load edge-case crashes (including descriptor pressure and transient SQLite operational failures).
* Added a dedicated Responder / Relay tab for launching Responder or NTLMRelay sessions with live output and easy stop/start controls.
* Captured hashes and relayed credentials are now parsed and stored in-project, with a new results table to review activity per host.
* Hardened SQLite operations with integrity checks, consistent backups, and a standalone repair script to recover corrupted project files.
* Expanded smoke-test coverage (scan import, save/load, credential capture) and enabled headless Qt execution for CI environments.
